# 现有下载器优化任务：高速下载模式 + 网页资源分类

你现在需要继续开发已经存在的本地下载器。请先检查当前项目代码、目录结构和已有功能，然后在原有项目基础上进行增量修改。

**重要：不要重写整个项目，不要删除已有功能，不要仅输出修改建议。请直接修改代码、运行测试并修复问题。**

## 一、新增高速下载开关

在下载器主界面新增一个明显的「高速下载」开关，用户可以随时开启或关闭。

### 1. 高速模式的行为

关闭时：
- 使用现有下载策略和默认并发参数。
- 保持当前下载器的正常运行方式。

开启时：
- 自动提高合理范围内的全局下载并发数。
- 在可配置范围内提高单域名并发数，但必须遵守网站的访问限制。
- 使用异步流式下载，避免不必要的内存占用。
- 对支持 HTTP Range 的大文件，允许将文件分块并发下载，完成后按正确顺序合并。
- 根据文件大小、网络状况、服务器响应和当前并发任务数量，决定是否启用分块下载。
- 对小文件避免分块下载带来的额外开销。
- 对同一服务器进行适当的并发限制，避免因并发过高导致限速、连接失败或 HTTP 429。
- 根据实际下载速度、超时率、失败率等指标动态调整并发度，必要时自动降低并发。
- 合理复用 HTTP 连接，控制连接池和连接超时。
- 优先采用稳定的异步下载和调度机制，不要为了追求速度而无限创建线程或协程。
- 保留失败重试、任务取消、暂停、任务状态持久化和断点续传能力。

### 2. 大文件分块下载

针对服务器支持 Range 请求的大文件，实现可选的多连接分块下载：

1. 获取文件大小并检查服务器是否支持可靠的 Range 请求。
2. 将文件划分为多个字节区间，使用多个连接下载不同区间。
3. 将每个区间写入独立临时分块文件，或者使用经过验证的安全随机访问写入方案。
4. 所有分块下载成功后，按照字节顺序合并或确认最终文件完整。
5. 校验文件总大小，条件允许时检查服务器提供的校验和。
6. 当服务器不支持 Range、响应不一致、文件发生变化或分块下载失败时，安全回退至普通下载。
7. 暂停或中断后保存分块进度，恢复时验证已下载区间，避免重复下载或文件损坏。
8. 确保多个任务不会同时覆盖同一目标文件。

不要假定所有服务器都支持分块下载。对于动态内容、压缩响应或缺少可靠文件标识的资源，优先使用普通下载。

### 3. 高速模式配置

提供以下可调整参数：
- 全局最大并发数。
- 单域名最大并发数。
- 大文件分块阈值。
- 单文件最大分块连接数。
- 网络连接超时与重试策略。

请为高速模式设置合理的默认值，并设置明确的最大上限。不要默认使用极端并发参数。

建议将高速模式作为一个可持久化的配置项，并在界面上显示当前运行模式及并发设置。

### 4. 下载速度与状态反馈

新增或优化以下信息：
- 单文件实时下载速度。
- 全局总下载速度。
- 已下载数据量和文件总大小。
- 当前活动连接数。
- 当前是否使用分块下载。
- 预计剩余时间（仅在数据足够时显示）。
- 高速模式启用状态。

速度统计应使用合理的采样窗口，避免因瞬时波动导致数字剧烈跳动。

### 5. 高速模式的性能要求

- 不得将无限并发作为高速模式的实现方案。
- 不得通过绕过登录、付费限制、验证码、访问控制或网站限速来提高速度。
- 不得在同一文件上发生错误的并发写入。
- 不得因启用高速模式而破坏原有下载任务的暂停、恢复、取消和断点续传功能。
- 对磁盘写入速度、网络带宽、服务器限速等瓶颈进行合理处理。
- 不宣称可以突破本机网络带宽或服务器端速度限制。

## 二、网页解析界面新增资源分类区域

在现有的「解析网页」界面中新增一个独立、清晰的「发现的资源」区域。

解析网页时，将嗅探到的可下载资源统一收集、去重、分类，并以可交互的列表形式展示。

### 1. 资源分类

至少支持以下分类：

- 文档：PDF、DOC、DOCX、TXT、RTF、ODT 等。
- 表格：XLS、XLSX、CSV、ODS 等。
- 演示文稿：PPT、PPTX、ODP 等。
- 压缩包：ZIP、RAR、7Z、TAR、GZ 等。
- 图片：JPG、JPEG、PNG、GIF、WEBP、SVG、BMP、TIFF 等。
- 视频：MP4、MKV、MOV、AVI、WEBM 等。
- 音频：MP3、WAV、FLAC、AAC、M4A、OGG 等。
- 程序与安装包：EXE、MSI、MSIX、APK、DMG、DEB、RPM 等。
- 数据与其他文件：JSON、XML、SQL、数据库文件及其他可识别类型。
- 未知类型：无法可靠识别类型的资源。

分类规则必须可以扩展，建议将扩展名映射与 MIME 类型映射集中管理。

### 2. 资源识别方式

综合使用以下信息识别资源类型：
- URL 路径中的文件扩展名。
- HTTP Content-Type。
- Content-Disposition 中的文件名。
- HEAD 请求或必要时的轻量级 GET 请求。
- 网页中的 a、source、video、audio、img、iframe 等相关元素。
- 网页中明确提供的下载链接及适当的公开资源地址。

注意：
- 不能仅凭 URL 后缀就认定资源真实类型。
- 部分下载地址没有文件扩展名，应结合响应头识别。
- 不要默认把普通网页、导航链接、广告链接或追踪链接当作可下载文件。
- 对需要登录、动态令牌或特殊授权的资源，标记为可能需要授权，不得伪造可下载状态。
- 对无法确定的资源保留「未知类型」分类，不要随意猜测。

### 3. 分类界面设计

在网页解析页面新增分类标签或侧边栏，至少包含：

- 全部资源。
- 文档。
- 表格。
- 演示文稿。
- 压缩包。
- 图片。
- 视频。
- 音频。
- 程序与安装包。
- 数据与其他文件。
- 未知类型。

每个分类显示资源数量，例如「文档（24）」。

点击分类后，仅显示该类别的资源；切换分类不应重新发起网页解析请求。

每条资源至少显示：
- 选择框。
- 文件名或推断出的名称。
- 文件类型。
- 文件大小（未知时显示「未知」）。
- 来源网页或域名。
- 资源 URL 的简要信息。
- 资源状态，例如「待下载」「可能需要授权」「不可访问」「类型未知」。

提供搜索框，可以按文件名、扩展名或域名筛选资源。

支持按文件名、类型、大小和来源排序；未知值应有一致的排序规则。

### 4. 批量选择和下载

在资源列表上方提供：
- 全选当前分类。
- 取消选择。
- 反选当前分类。
- 选择全部可下载资源。
- 按文件类型批量选择。
- 将选中资源加入下载队列。
- 下载当前分类。
- 下载全部符合条件的资源。

加入下载队列时：
- 复用现有下载任务管理模块。
- 保留资源 URL、文件名、来源网页和 MIME 类型等信息。
- 使用现有下载目录配置。
- 处理重复 URL 和目标文件重名。
- 在加入队列前检查资源是否已经存在于任务列表中。
- 明确显示加入成功、重复跳过和失败数量。

不能把未经确认的网页地址直接当作文件直链下载。

### 5. 网页解析过程的性能和稳定性

- 大型网页中发现的资源应分批处理，避免界面卡顿。
- 对资源进行去重，规范化 URL 时不得破坏查询参数中可能影响下载的签名或令牌。
- 资源探测使用有限并发，不得对网页中的每一个链接都进行无节制的 HEAD 请求。
- 对 HEAD 不支持的服务器，按需使用有大小和时间限制的 GET 探测。
- 避免下载完整文件来判断文件类型。
- 正确处理相对 URL、重定向、编码后的文件名及国际化文件名。
- 对外部 URL 和重定向目标执行安全检查，防止 SSRF 和内网地址访问。
- 对 JavaScript 动态生成的链接，在现有技术架构允许的情况下提供可选的浏览器渲染解析能力。
- 如果资源无法提取，显示具体原因，而不是静默忽略。

## 三、界面整合要求

保持现有界面的整体风格，不要另建一个与原项目无关的下载器。

主界面新增高速下载开关。

网页解析界面新增资源分类区域。

两个功能应共用现有的任务队列、配置管理、下载目录管理和状态更新机制，避免出现两套互不兼容的任务系统。

对于任务数量较多的场景，采用分页、虚拟列表或合理的分批渲染机制。

## 五、必须执行的测试

高速下载：
- 开关切换后配置正确生效。
- 多文件并发下载。
- 大文件分块下载及正确合并。
- 服务器不支持 Range 时的回退。
- 分块中断后的恢复。
- 服务器返回不一致的文件大小或验证器时的安全处理。
- 并发写入、重名文件和取消任务。
- HTTP 429、超时、断网和磁盘错误。
- 高速模式关闭后恢复正常调度策略。

资源分类：
- 各类扩展名与 MIME 类型映射。
- 没有扩展名的下载链接。
- Content-Disposition 指定文件名。
- 相对 URL 和重定向。
- URL 去重。
- 分类数量统计。
- 搜索、排序、全选和反选。
- 将选中资源正确加入下载队列。
- 大量资源下的界面响应。
- SSRF 和恶意 URL 拦截。

尽可能使用本地模拟 HTTP 服务进行测试，不要依赖不稳定的第三方网站。
