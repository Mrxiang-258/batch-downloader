# 项目任务：开发一个高效、易用的本地批量下载器

你是一名资深 Python 工程师、全栈开发工程师和自动化工具开发专家。请在我的本地计算机上开发一个完整、可运行、方便日常使用的下载器。不要只提供代码示例或技术方案，而要实际创建项目文件、编写代码、安装依赖、运行测试，并尽可能完成部署。

## 一、核心目标

开发一个本地运行的下载器，用户只需输入网页 URL 或一批 URL，选择本地保存目录，即可自动下载文件。

产品应当具备简洁、直观的图形界面，操作简单，不需要用户频繁使用命令行。

## 二、核心功能

### 1. 多种下载方式
- 支持输入单个文件直链进行下载。
- 支持批量粘贴多个 URL，每行一个。
- 支持从 TXT、CSV 文件导入大量下载链接。
- 支持输入网页地址，分析网页内容并提取可直接下载的文件链接。
- 支持批量解析多个网页，并将提取出的下载任务加入队列。
- 支持常见文件类型，包括 PDF、DOCX、XLSX、PPTX、ZIP、RAR、图片、视频、音频及其他常见文件。
- 自动识别文件名、文件类型、文件大小和下载地址；无法识别时提供合理的备用方案。
- 对网页中无法直接提取的文件，不得伪造下载成功状态，应明确显示失败原因。

注意：普通网页 URL 不一定是文件直链。请区分网页解析与文件下载两种流程。对于需要登录、JavaScript 渲染、动态令牌或特殊授权的网页，明确提示限制；在合法授权范围内，优先采用官方 API、公开下载链接或用户提供的有效会话。

### 2. 指定目录与文件管理
- 允许用户通过文件夹选择器指定下载目录。
- 支持为不同批次设置不同的保存目录。
- 默认保存到用户设置的目录。
- 自动创建必要的子目录。
- 可选按文件类型、来源网站或任务批次分类保存。
- 自动处理重名文件，避免意外覆盖。
- 支持用户选择覆盖、跳过或自动重命名。
- 记录文件的实际保存路径，并提供打开文件或打开所在文件夹的操作。

### 3. 大批量下载
必须将大批量下载作为核心设计目标，而不是简单循环执行下载。

- 支持至少数千条 URL 的任务导入、管理和排队；在合理的本机资源限制下，避免界面卡死或内存占用失控。
- 使用异步 I/O 或其他合适的并发方案。
- 支持配置全局并发数、单域名并发数和连接超时时间。
- 提供任务队列、等待中、下载中、已完成、失败、已暂停等状态。
- 显示单任务进度、总任务进度、下载速度、已下载大小和预计剩余时间（能够可靠计算时）。
- 支持暂停、继续、取消单个任务，以及暂停、继续、取消整批任务。
- 支持失败任务重试，并允许设置最大重试次数。
- 对 HTTP 429、5xx、网络超时等情况使用合理的退避重试策略。
- 遵守网站的访问限制和服务条款，不得通过无限并发、绕过访问控制或规避反爬措施实现下载。
- 对同一 URL 进行去重，并允许用户自行选择是否重新下载。

### 4. 断点续传与稳定性
- 在服务器支持 HTTP Range 且响应验证通过时，实现断点续传。
- 正确处理 ETag、Last-Modified、Content-Length 和 Content-Range 等响应头。
- 如果服务器不支持续传，自动回退为重新下载，并向用户说明。
- 下载文件先写入临时文件，成功后再安全地提交为最终文件。
- 检查磁盘空间、文件写入错误、权限不足和网络中断。
- 下载完成后校验文件大小；在服务器提供可靠校验和时进行完整性验证。
- 应用意外退出或计算机重启后，能够恢复任务队列及可恢复的下载进度。
- 不允许将不完整文件误标为下载成功。

### 5. 图形界面
开发一个现代化、简洁的本地 Web UI，优先采用 FastAPI + HTML/CSS/JavaScript，或选择更合适且易维护的方案。

界面至少包含：

- 下载链接输入框。
- 网页解析与批量导入入口。
- 目标目录选择与显示。
- 并发数及下载选项设置。
- 开始下载按钮。
- 下载任务列表。
- 实时进度条、速度及状态显示。
- 失败任务重试按钮。
- 暂停、恢复、取消和清理已完成任务的操作。
- 下载历史和失败原因查看。
- 搜索、筛选和批量选择任务。
- 适用于 Windows 桌面浏览器的布局。

所有耗时任务必须在后台执行，界面应保持响应。使用 WebSocket、SSE 或合理的轮询机制更新任务状态。

### 6. 本地运行与安全
- 优先兼容 Windows 11。
- 提供清晰的项目目录结构和依赖文件。
- 提供一键启动脚本，例如 `start.bat`。
- 启动后自动打开本地 Web UI。
- 提供 `config.json` 或类似配置文件，用于设置默认下载目录、并发数和其他参数。
- 不要求用户部署云服务器，也不依赖付费 API。
- 默认只允许访问合法、可公开访问或用户明确授权的下载资源。
- 防止 SSRF、目录穿越、任意本地文件读写和恶意 URL 利用。
- 网页解析必须限制可访问的网络地址，避免访问 localhost、内网地址、云元数据地址及其他非公开目标；重定向后的目标也必须重新检查。
- 通过安全的文件名处理和路径校验，确保文件只能保存到用户授权的下载目录。
- 不在日志中泄露密码、Cookie、令牌或其他敏感信息。
- 不自动执行下载得到的文件。

## 三、推荐技术架构

请根据实际需求采用可靠、易维护的技术：

- 后端：Python + FastAPI。
- 下载引擎：aiohttp 或 httpx；如果需要更成熟的下载管理能力，可评估其他合适方案。
- 网页解析：BeautifulSoup 等工具，必要时提供可选的浏览器渲染模块。
- 任务持久化：SQLite。
- 前端：HTML、CSS、JavaScript，或适合本地运行的轻量级前端框架。
- 测试：pytest，并建立可控的本地 HTTP 测试服务器。

不要为了使用某个技术而强行增加复杂度。优先保证可靠性、批量处理能力、易安装和易维护。

## 四、开发流程

请按照以下步骤实际执行：

第一步：检查当前环境、操作系统、Python 版本和已有项目文件。若当前目录已有项目，先检查再修改，不要擅自删除或覆盖用户文件。

第二步：制定简洁的技术方案和项目目录结构，说明关键设计决策。

第三步：直接创建完整项目文件，实现核心功能。不要只输出代码片段，也不要把未实现的功能伪装成已经实现。

第四步：安装必要依赖。遇到网络或权限问题时，先诊断原因，再选择合理的解决办法，不要反复执行相同的失败命令。

第五步：运行自动化测试，至少覆盖：
- 单文件下载。
- 多 URL 批量下载。
- 网页解析。
- 文件重名处理。
- 暂停与恢复。
- 断点续传。
- 网络超时及失败重试。
- 服务器不支持续传的情况。
- 无效 URL 与恶意 URL 拦截。
- 任务重启后的恢复。
- 大量任务导入时的内存和界面响应情况。

第六步：修复测试发现的问题，重新运行相关测试。报告真实的测试结果，不得编造测试通过情况。

第七步：创建 Windows 一键启动脚本 `start.bat`，必要时增加初始化脚本和停止脚本。

第八步：给出清晰的使用说明，告诉我：
1. 项目文件在哪里。
2. 如何首次启动。
3. 如何输入单个或批量链接。
4. 如何指定下载目录。
5. 如何管理大量任务。
6. 如何恢复中断的下载。
7. 如何查看日志和排查问题。

## 五、验收标准

只有满足以下条件，才算完成第一版：

1. 能在本地实际启动，而不是只有源代码。
2. 可以下载一个有效的直链文件。
3. 可以从 TXT 文件导入大量 URL 并排队下载。
4. 可以输入公开网页并提取其中符合规则的下载链接。
5. 可以设置保存目录并正确处理重名文件。
6. 任务进度可以持续更新，且界面不会因下载任务阻塞。
7. 支持失败重试、暂停、恢复和可用条件下的断点续传。
8. 任务状态能够持久保存。
9. 关键安全检查和自动化测试能够运行。
10. 有清晰的一键启动方式和使用说明。

## 六、执行原则

- 直接开始检查环境并开发，不要只停留在方案讨论。
- 如果某个非关键需求不明确，请采用合理默认值继续推进。
- 如果确实需要我提供信息、授权或执行特殊操作，再提出一个具体问题。
- 优先完成可运行的最小完整版本，再逐步增加高级功能。
- 每个阶段简要汇报完成情况、实际测试结果及尚未解决的问题。
- 不要为了追求复杂架构而过度设计。
- 不得虚构执行结果，不得将占位功能说成已实现功能。
